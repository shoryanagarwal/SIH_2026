TRACE-X — AI-Based Early Anomaly & Degradation Screening of Electronic Components

TRACE-X is an AI-assisted screening system designed to identify anomalous and potentially degrading electronic components during burn-in testing.

Traditional screening mainly relies on fixed parametric limits. However, a component can remain within its absolute specification limits while showing abnormal behavior compared with other components in the same lot or developing a degrading trend over time.

TRACE-X combines Machine Learning, Deep Learning, temporal drift analysis, and risk assessment to identify such potential latent defects at an early stage.

Problem

High-reliability electronic components undergo burn-in and environmental stress screening before deployment in critical systems.

A conventional static threshold-based approach can detect obvious failures, but may miss components that:

Remain within absolute specification limits
Behave abnormally compared with other components in their lot
Show gradual degradation over time
Are likely to become unsafe at a later stage of burn-in

For example:

Lot average leakage = 10 µA
Component leakage = 45 µA
Absolute maximum limit = 50 µA

A static threshold would allow the component to pass, even though its behavior is significantly different from its peers.

TRACE-X provides an additional dynamic screening layer to identify such cases.

Solution

TRACE-X analyzes burn-in measurements across multiple time points and combines current anomaly detection, degradation analysis, future prediction, and risk assessment.

Key Modules
1. Dynamic Anomaly Detection

TRACE-X uses Isolation Forest to identify components that exhibit unusual behavior based on their burn-in measurements.

Instead of relying only on fixed pass/fail limits, the system evaluates the overall behavior of the component and generates an anomaly signal.

2. Drift Engine

The Drift Engine analyzes how component parameters change throughout the observed burn-in period.

Currently, measurements are analyzed at:

0 hours
24 hours
48 hours
96 hours

The monitored parameters include:

Temperature
VCE
Leakage
Breakdown Voltage

The engine evaluates:

Change between time points
Rate of change
Percentage change
Acceleration of degradation
Trend behavior
Instability

The resulting trend can be characterized as:

STABLE
SLOW_DEGRADATION
ACCELERATING
INTERMITTENT_INSTABILITY

The Drift Score is normalized to a 0–100 scale, with leakage used as the primary parameter for the numerical drift score while the other parameters provide supporting degradation information.

3. LSTM-Based 168h Prediction

TRACE-X uses a Long Short-Term Memory (LSTM) neural network to model temporal relationships in burn-in measurements.

The current model uses:

4 time steps × 4 parameters = 16 input values

Input time points:

0h → 24h → 48h → 96h

The model predicts the corresponding parameter values at:

168h

The four predicted parameters are:

Temperature
VCE
Leakage
Breakdown Voltage

LSTM is used because burn-in measurements form a sequence over time, allowing the model to learn temporal relationships within the degradation process.

4. Risk Engine

The Risk Engine combines the different signals generated by TRACE-X.

Current weighting:

Risk Score =
    40% × Anomaly Score
  + 35% × Drift Score
  + 25% × Prediction Risk

The final risk score ranges from 0–100.

Risk Score	Decision
< 40	PASS
40–69	REVIEW
≥ 70	EARLY REJECT

An uncertainty margin is also applied around the decision boundaries, routing borderline cases toward REVIEW.

5. Explainable Screening

TRACE-X provides supporting evidence along with the final screening decision, including:

Anomaly level
Drift behavior
Parameter changes
Predicted 168h values
Prediction-based risk
Final risk score
Screening recommendation

This makes TRACE-X a decision-support system rather than simply a black-box prediction model.

Dataset

TRACE-X uses the NASA IGBT aging dataset as the base dataset.

The dataset was used to construct a synthetic burn-in representation of IGBT components across different lots and degradation stages.

The resulting representation contains measurements across multiple burn-in stages for:

Temperature
VCE
Leakage
Breakdown Voltage

Component and lot information, along with class information for evaluation, are also available in the dataset.

Feature Leakage Prevention

The following are not used as predictive input features:

Component_ID
Lot_ID
True_Class

True_Class is retained as ground truth for evaluation.

Data Splitting & Preprocessing

The deep learning pipeline uses lot-wise train/validation/test splitting:

35 lots → Training
7 lots  → Validation
8 lots  → Testing

The split is performed by lot to reduce the possibility of components from the same lot appearing across different datasets.

Feature scaling is performed by fitting the scaler only on the training data. The same fitted scaler is then applied to validation and test data.

This helps prevent information from the validation or test sets from influencing training preprocessing.

Evaluation
Anomaly Detection

The anomaly detection system can be evaluated using:

Precision
Recall
F1-score
Confusion Matrix
False Negative Rate

False negatives are particularly important because a defective component incorrectly classified as safe represents a potential defect escape.

168h Prediction

The LSTM regression model is evaluated using:

MAE
MSE
RMSE

The primary prediction objective is to minimize the difference between predicted and actual 168-hour values.
                 
End-to-End Workflow
User uploads burn-in component data.
Frontend sends the data to the Node.js backend.
Backend communicates with the TRACE-X AI service.
Data is preprocessed.
Isolation Forest generates an anomaly signal.
Drift Engine analyzes degradation behavior.
LSTM predicts 168-hour parameter values.
Prediction-based risk is calculated.
Risk Engine combines anomaly, drift, and prediction signals.
TRACE-X generates a final screening recommendation.
Results are displayed on the dashboard.
